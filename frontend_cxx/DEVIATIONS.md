# frontend_cxx: deliberate deviations from the Python frontend


## A: deliberate differences from the Python frontend

| # | Where | Python | frontend_cxx | Why |
|---|---|---|---|---|
| A1 | `system_fingerprint` | `vllm-0.32.0-<VllmConfig.compute_hash()[:8]>` | `vllm-0.32.0-<sha256(args-json)[:8]>` (same length); `FE_SYSTEM_FINGERPRINT` overrides, `--fingerprint-mode none/custom` honoured | compute_hash() hashes the whole Python VllmConfig; not reproducible in C++. No client reads it. |
| A2 | `/metrics` | default registry: `python_gc_*`, `python_info`, `process_*` (of the API server), `vllm:*`, `http_*` | no `python_gc_*` / `python_info`; `process_*` of frontend_cxx; `vllm:*` from fe_engine (byte-identical families); `http_*` recorded when the route handler returns (async non-streaming and streaming requests count as 2xx with the setup duration) | no Python runtime; the instrumentator semantics are approximated. Metric names and labels are unchanged (verified: identical family + label-key set apart from python_*). No gzip response encoding (clients that send `Accept-Encoding: gzip` get identity, which they accept). |
| A3 | HTTP server | uvicorn: no idle limit before the first request, no body size limit, `100 Continue` sent when the app reads the body | idle connections that never sent a request close after 300 s; bodies > 1 GiB get 413; `100 Continue` sent right after the headers | resource safety; not client-visible for well-behaved clients |
| A4 | images | `http(s)://` image URLs are fetched | 400 `frontend_cxx: only data: image URLs are supported` | no HTTP client in the binary; no client sends remote URLs |
| A5 | `n > 1` (chat / completions) | AsyncLLM fan-out into child requests | 400 `frontend_cxx: n > 1 is not supported` | no client uses it; fe_engine has no fan-out |
| A6 | completions with a list of several prompts | one choice per prompt | 400 (single prompt: string, token-id list, or a one-element list) | no client uses it |
| A7 | error ordering | pydantic validation -> `_check_model` 404 -> render errors | fe_render validates and renders in one call, then the model check | only a request that is valid, fails rendering AND names an unknown model differs (render 400 instead of the 404) |
| A8 | background Responses (`background: true`) | final stored response built by the non-streaming path (reasoning item `status: null`) | built from the streaming state (reasoning item `status: "completed"`) | rarely used; store/GET/cancel semantics otherwise match |
| A9 | Responses structural tag | applied | applied, from the chat form of tools / tool_choice | - |
| A10 | CORS middleware | Starlette CORSMiddleware with `--allowed-origins` (empty in production) | not implemented | production passes no origins |
| A11 | SSE delta chunking | `RequestOutputCollector` merges deltas when the asyncio consumer lags (timing-dependent) | the same merge rule, applied only when the client's socket is congested (> 1 MiB pending) | frontend_cxx keeps up with the engine, so it merges less often; the concatenated text, tool arguments, finish/usage chunks are identical |
| A12 | `vllm:tool_call_parser_invocations_total` | `mode="streaming"` counts one per `parse_delta` call in the tool-call phase, i.e. per (possibly merged) delta | same points (fe_parser hook `ParserOptions::on_tool_parser_invocation`), so the streaming counts follow A11: under load Python merges more deltas and counts fewer; non-streaming counts, labels, HELP/TYPE and `_created` are identical | follows from A11. Background Responses without `stream` count one `non_streaming` parse like Python (a re-parse of the final text at the end, metrics only), not per delta (A8) |
| A13 | HTTPS | uvicorn + Python `ssl`: TLS >= 1.2, no ALPN (httptools), asyncio handshake timeout 60 s, `--enable-ssl-refresh` reloads changed cert files, HTTP/1.1 only | OpenSSL in fe_http (DESIGN "HTTPS in fe_http"): TLS >= 1.2 and the same default TLS 1.2 cipher list; ALPN answers `http/1.1` when offered (still no HTTP/2); handshake timeout 10 s (`FE_TLS_HANDSHAKE_TIMEOUT_S`); `--enable-ssl-refresh` ignored with a warning (cert files are read once at start); encrypted keys fail instead of prompting; bad TLS files exit 2 before the engine wait; `ssl_*` keys excluded from the A1 fingerprint hash | resource safety on a public port; no client depends on the rest. Restart to pick up renewed certificates |
| paths outside `/v1/` (normpath-clean), `/health`, `/metrics`, `/version` get 404 `{"detail": "Not Found"}`, key or not; http(s) media URLs to internal / unresolvable hosts get 400 "media URL not allowed: ..." | the same allowlist, byte-identical 404, when `FE_ROUTE_ALLOW` (or that `--middleware` entry) is set; default off. Media URLs: every http(s) URL is refused (A4), with A4's message | frontend_cxx never fetches remote media, so the SSRF check has nothing to guard; the status (400) matches |

## F (image): deliberate differences from the Python image path

| # | Where | Python (vLLM 0.32.0, Pillow 13.0.0) | frontend_cxx (fe_image) | Why |
|---|---|---|---|---|
| F1 | image formats | `Image.open(formats=ALLOWED_IMAGE_FORMATS)`: JPEG/MPO, PNG/APNG, GIF, WebP and also AVIF, BMP/DIB, BLP, CUR/ICO, DCX, DDS, FITS, FLI, FTEX, GBR, ICNS, IM, IMT, IPTC, JPEG2000, MCIDAS, MSP, PCD, PCX, PIXAR, PPM, PSD, QOI, SGI, SPIDER, SUN, TGA, TIFF, XBM, XPM, XVTHUMB | JPEG (incl. MPO frame 0), PNG (incl. APNG frame 0), GIF (frame 0), WebP (still + animated frame 0); the rest -> `ImageError(kUnsupported)` | the four formats the OpenAI image API accepts; the others are not sent by API clients. A should answer 400 (Python would have accepted the image). |
| F2 | EXIF transpose of malformed EXIF | `ImageOps.exif_transpose` re-serialises the EXIF (`Exif.tobytes()`) after rotating; if that raises, vLLM's `normalize_image` suppresses it and the image is NOT rotated | fe_image rotates whenever Pillow reads a valid Orientation (2..8); the re-serialisation is not ported | porting TiffImagePlugin's writer validation is out of scope; only EXIF that Pillow can read but not write differs (not seen in camera / Pillow-written EXIF) |
| F3 | `mm_processor_kwargs` / `media_io_kwargs` per request | change the processor / decoder and enter the mm_hash | not implemented (A rejects them) | not used by clients |
